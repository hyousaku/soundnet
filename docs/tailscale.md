# Tailscale 経由での遠隔配信

SoundNet を公開インターネット越しに使う場合の注意点と手順。

---

## mDNS は Tailscale を越えない

Tailscale はレイヤー3のオーバーレイで、マルチキャストをフォワードしない。したがって `_soundnet._udp.local.` による自動発見は遠隔ピアに届かない。

代わりに、UI の「Add host…」ダイアログを使う。ピアの tailnet アドレスと control port を手入力する（`100.x.y.z` と `7788`）。tailnet のアドレスは CGNAT レンジ `100.64.0.0/10` から配られるので、`tailscale status` に出る `100.` で始まるアドレスがそれ。

手動で追加したホストは設定ファイルに保存され、再起動後も残る。

---

## このノードは tailscale0 をピンして使う

UI の「This node」→「Egress interface」で `tailscale0` を選ぶ。

理由: エンジンは1つのアドレスをピアに広告し、ピアはそのアドレスへ音声を送る。LAN アドレスをピンしたままだと、インターネット経由のピアはそのアドレスに到達できない。

ただし正直な注意がある: **ノードは広告するアドレスが1つだけなので、tailscale0 をピンするとローカル LAN トラフィックも tunnel を経由する**。同じ部屋の2台間でも余計な暗号化とホップが発生する。

現在のところ、ピア毎のアドレス選択はできない。最初の実験は **インターネットリンクのみに限定することを勧める**。

---

## ピンニングでパケットサイズも決まる

SoundNet は、ピンしたインターフェースの MTU から最大 UDP ペイロードを計算する。`tailscale0` は MTU 1280 がデフォルト。Ethernet は 1500。

**ピンすることでこれが正しくなる、という向きの話である。** ピンしていなければエンジンはどのインターフェースから出ていくか分からないので Ethernet の 1500 を前提にする。実際の経路が MTU 1280 の tunnel だと、チャンネル数によってはデータグラムが 1280 を超えて IP フラグメント化される。

フラグメント化は避けたい。フラグメント化されたデータグラムは all-or-nothing で、1フラグメントの喪失で全体が失われる。しかもカーネルが下で再組立てまたは破棄するため roc からは見えず、FEC が最も吸収しにくいロスパターンになる。つまり**症状が重いうえに計器に映らない**。

エンジンが読み取った MTU は sender を開くたびにログに出る。食い違いを疑うときは、カーネル側の値と突き合わせる:

```bash
ip link show tailscale0        # MTU 1280 のはず
journalctl -u soundnet-engine@$USER | grep -i mtu
```

---

## direct vs relay が分かれ目

`tailscale status` を実行してピアの行を見る。

- **`relay`** と出ていたら、トラフィックは DERP リレーサーバー経由。遅延が数十〜数百 ms 増えるので、SoundNet 側のどの設定をいじっても音には間に合わない。**ここが `direct` になるまで、他の調整は全部意味がない。**
- **`direct`** なら、接続が直通。これ以降の調整に進む。

---

## 起動設定

これでまず試す:

- `target_latency_ms`: 80 以上（UI で最大 200）
- FEC: オン
- `frames_per_period`: 256

---

## 用途の現実的な限界

このセットアップは以下に向く:

- 遠隔配信・モニタリング
- 別室の音声
- 遅延タワー・録音・ストリーミング配信の送信元

**向かない**: イヤモニタリングや演奏に合わせて聴く必要があるもの。そういった用途は 5 ms 以下の end-to-end 遅延が要る。インターネットパスではそれは出ない。

参考: 音は空気中で約 3 ms/m 進む。20〜30 ms は 7〜10 m 相当で、大きな部屋なら既に存在している距離である。

---

## まだ実装で確かめていないこと

**このガイドと MTU 処理は、実装の理屈から推論したもので、Tailscale 越し end-to-end で実際に動かして計測したわけではない。**

誰かが最初に試すときは、以下を記録してほしい:

- `tailscale status` に `direct` と出たか
- 実際に使える `target_latency_ms`
- `xrun` のカウント

## トラブルシューティング

| 症状 | 原因と対策 |
|---|---|
| リモートノードが UI に現れない | mDNS は Tailscale を越えない。「Add host…」で手入力する。 |
| ノードは現れたが、ルートが「retrying」のまま | ノードが広告しているアドレスにピアが到達できない。「Egress interface」で `tailscale0` をピンしているか確認。 |
| 音が来るが、ブツブツで FEC が効かない | MTU またはリレー。`tailscale status` が `direct` か確認。IP フラグメンテーションが起きていないか確認（`ip link show tailscale0` で MTU）。 |
